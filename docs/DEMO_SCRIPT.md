# AttendAI — Judge Demo Script (about 7 minutes)

All accounts use the password **`Demo@2026`**. The login page has one-click buttons for each role.
The data is fictional.

**Story:** Rohan Verma (S003) has been slipping. The latest attendance sheet (1 Sep) has not been
imported yet, so he currently shows **WARNING**.

## 1. Admin imports attendance (1 min)

1. Click **Admin (all departments)**.
2. Point at the dashboard: 14 students, risk distribution, attendance bands, highest-risk students,
   each with its *reason*.
3. **Upload attendance** → choose `sample_data/attendance_invalid_example.csv` → *Upload and
   process*.
   > "Every row is validated first. One bad row and nothing is saved, and here is exactly what's wrong."
4. Choose `sample_data/attendance_sample.csv` → *Upload and process* (tick *Replace existing
   records* if it was already uploaded).
   > "24 rows processed for 8 students, and the system shows which students' risk changed:
   > Rohan and Vihaan → CRITICAL, Aarav → WARNING, Meera improved."

## 2. Explainability (2 min)

5. Click **Rohan Verma** in the risk-change table (or *View critical students*).
6. Walk through the risk card:
   * Current **74.5%** (108/145 classes), Projected **72.8%**, Target **75%**
   * Trend **Decreasing**: recent 70.1% vs earlier 81.0%
   * *Why this rating*: "Projected attendance of 72.8% is below the 75% target, assuming the recent
     rate of 70.1% … continues for the 87 remaining classes …"
   > "It doesn't just show red. It says why, and with what assumption."
7. **Recovery plan**: attend the next **3** classes in a row to return to 75% (111/148), and at least
   **66 of the 87** remaining classes to finish the term above target.
8. **Recovery calculator**: change *Classes attended* and watch it recompute. Set the target to 100 to show
   it refuses impossible plans.
9. Subject table: DBMS and Operating Systems are CRITICAL even though Data Structures is fine.
10. *(Optional)* Open **Kabir Singh**: Operating Systems is *not recoverable this term*, so the
    recommended action is the condonation route.

## 3. Mentor (1 min)

11. Sign out → **Mentor (CSE students)**: only the 8 assigned students, *Students needing attention*,
    mentor alerts generated by the import ("Rohan Verma is now CRITICAL (was WARNING) …").
12. **Condonation**: Kabir's pending medical request.

## 4. Student (1 min)

13. Sign out → **Student – Rohan Verma**: own dashboard only, same explanation in the first person,
    alert about the risk change.
14. Submit a condonation request ("Hospitalised for dengue, 3–14 Aug …") → status **PENDING**.

## 5. Review (1 min)

15. Sign out → **Mentor** → Condonation → Rohan's request → **Approve** with a comment.
16. Sign out → **Student** → status **APPROVED**, the comment, history and an alert.

## 6. Department reporting (1 min)

17. Sign out → **Exam Cell** (read-only) → **Department reports** → CSE: totals, shortage count,
    risk distribution, subject pattern, shortage list with condonation status, **Export CSV**.
18. *(Optional)* **HOD, ECE**: sees only ECE. Opening a CSE student shows *Access denied* (enforced by
    the server, not just hidden).

> "AttendAI turns attendance from a passive percentage into an early-warning and intervention workflow."
